# Release v1.7.0 — Multi-asset deposit vault, oracle pricing & audit remediations

**Date:** 2026-09-29
**Package:** `@concrete-xyz/earn-v2-core@1.7.0`

---

## Overview

This release ships the headline feature of the v1.7 cycle: a **multi-asset deposit async vault** (`ConcreteMultiAssetDepositAsyncVault`) that accepts whitelisted non-base tokens, values them in base-asset units through a pluggable **asset pricer**, and routes them straight to a dedicated **`MultiAssetStrategy`**. Supporting it are a Chainlink-backed **`OracleModule`** (with L2 sequencer uptime gating and timelock integration), two pricers (`OneToOneAssetPricer`, `OracleAssetPricer`), a new `PRE_MULTI_DEPOSIT` hook point, and a per-token **`MultiAssetDepositCapHook`**.

It also moves the deposit / withdraw execution bodies out of `ConcreteStandardVaultImpl` into `UserActionsLib` (EIP-170 headroom), tightens ERC-4626 `maxMint` / `maxRedeem` accuracy around minimum transaction amounts, and incorporates the **Earn v1.7 audit remediations** (FIND-002, FIND-004, FIND-006, FIND-007, FIND-009).

Vault implementations and hooks are bumped on-chain to `IContractId.ID() = 1.7.0` (see §8).

---

## What's New

### 1. Multi-asset deposit async vault (`ConcreteMultiAssetDepositAsyncVault`)

A new vault flavour (`FLAVOUR() = 8`) extending `ConcreteAsyncVaultImpl`. It keeps base-asset (`asset()`) accounting but accepts deposits denominated in other, whitelisted tokens.

**Entry points:**

| Function | Access | Purpose |
|---|---|---|
| `deposit(address depositAsset, uint256 assets, address receiver)` | Public | Base asset → inherited ERC-4626 `deposit` (idle balance + mint). Whitelisted non-base asset → priced to base value, shares minted, tokens pushed straight to the configured strategy. |
| `previewDeposit(address depositAsset, uint256 assets)` | View | Same validation as `deposit` (whitelist, config, Active strategy, non-zero base value), then previews on the base-equivalent value. |
| `configureMultiAsset(MultiAssetVaultManagerConfig, bytes)` | `VAULT_MANAGER`, `afterDelay` (TIER_2) | Dispatcher for `AddWhitelistedAsset`, `SetPricer`, `SetMultiAssetStrategy`. A single dispatcher keeps runtime bytecode under EIP-170. |
| `removeWhitelistedAsset(address)` | `VAULT_MANAGER`, **instant** | Delisting is a restrictive correction and is intentionally not timelocked (no `withYieldAccrual` either, so it stays reachable if a strategy view reverts). Existing allocations stay accounted for. |
| `isWhitelistedAsset` / `getWhitelistedAssets` / `getMultiAssetPricer` / `getMultiAssetStrategy` | View | Configuration introspection. |

**Non-base deposit flow** (`MultiAssetVaultHelperLib.multiAssetDeposit`, DELEGATECALL):

1. `prepareNonBaseDeposit` — asset whitelisted, pricer + strategy configured, strategy `Active`, `baseValue = pricer.convertToBase(...) != 0`.
2. `UserActionsLib.preDeposit(baseValue, …)` — standard `PRE_DEPOSIT` hook, min / max deposit enforcement against the base-equivalent value.
3. `PRE_MULTI_DEPOSIT` hook with the raw token and amount.
4. Pull `depositAsset` from the caller, `forceApprove` the strategy, call `IMultiAssetDepositStrategy.allocateFundsMultiAsset`, reset approval. Reverts `BaseAllocatedMismatch` unless the strategy books exactly `baseValue`.
5. Book `baseAllocated` into `cachedTotalAssets` and the strategy's `allocated`; defensive `cachedTotalAssets >= Σ allocated` check.
6. Emit `MultiAssetDeposit`, mint shares, emit `IERC4626.Deposit`, fire `POST_DEPOSIT`.

Non-base tokens never sit idle in the vault. `totalAssets()` for this flavour is the deposit-time base valuation of assets under strategy custody; later conversion spread / slippage is realized through the strategy's `adjustTotalAssets`, like any other PnL on `MultisigStrategy`.

**Storage:** new EIP-7201 namespace `concrete.storage.ConcreteMultiAssetDepositAsyncVaultStorage` (`whitelistedAssets`, `pricer`, `strategy`).

**New errors:** `AssetNotWhitelisted`, `AssetAlreadyWhitelisted`, `CannotWhitelistBaseAsset`, `CannotWhitelistShareToken`, `InvalidPricer`, `MultiAssetNotConfigured`, `MultiAssetStrategyNotActive`, `ZeroBaseValue`, `BaseAllocatedMismatch`, `InvalidMultiAssetStrategy`, `InvalidMultiAssetConfig`.

**New events:** `WhitelistedAssetAdded`, `WhitelistedAssetRemoved`, `MultiAssetPricerSet`, `MultiAssetStrategySet`, `MultiAssetDeposit(caller, receiver, depositAsset, assets, baseValue, shares)`.

### 2. `MultiAssetStrategy` and `IMultiAssetDepositStrategy`

`IMultiAssetDepositStrategy` is the opt-in extension a strategy implements to receive non-base deposits:

```solidity
function allocateFundsMultiAsset(address depositAsset, uint256 depositAmount, uint256 baseValue)
    external returns (uint256 baseAllocated);
```

`MultiAssetStrategy` (`FLAVOUR() = 8`) is a `MultisigStrategy` that implements it: it pulls the raw `depositAsset` from the vault, forwards it to the multisig, and adds `baseValue` to the base-denominated `vaultDepositedAmount` so `totalAllocatedValue()` moves in lockstep with the vault's `allocated`. `onlyVault`, `whenNotPaused`, reverts `ZeroMultiAssetAllocation` on zero inputs, and checks accounting validity. Emits `AssetsForwarded` and `AllocateFundsMultiAsset`. Base-asset flows are unchanged from `MultisigStrategy`.

### 3. Asset pricers (`IAssetPricer`)

`IAssetPricer.convertToBase(depositAsset, baseAsset, amount)` values a deposit in base units. Pricers are stateless per vault and can serve many vaults. Both implementations round down (never over-value a deposit) and return `amount` unchanged when `amount == 0` or `depositAsset == baseAsset`.

| Pricer | Behaviour |
|---|---|
| `OneToOneAssetPricer` (`src/pricer/`) | 1 unit = 1 unit, adjusted only for token decimals. For same-peg assets (e.g. stablecoins). |
| `OracleAssetPricer` (`src/pricer/`) | Two-legged: `amount * price(deposit) / price(base)`, decimal delta folded into one `mulDiv`. Prices from an immutable `OracleModule`; the shared quote currency cancels. The ratio inherits the looser of the two staleness windows — give the base-asset feed the tightest `maxDelay`. |

### 4. `OracleModule` (`src/periphery/oracle/OracleModule.sol`)

A Chainlink price-feed registry with per-asset validation, consumed by `OracleAssetPricer`.

| Function | Access | Purpose |
|---|---|---|
| `setOracle(asset, feed, minPrice, maxPrice, maxDelay, validateCaps, validateStaleness)` | Owner, `afterDelay` (TIER_2) | Installs / repoints a feed. Feed decimals must match the module's immutable `decimals`; feed answer must be live and in range at configuration time. |
| `getPrice(asset)` | View | Returns the validated price. Reverts `InvalidOracle`, `PriceOutOfBounds`, `StalePrice`, and — when a sequencer feed is set — `SequencerDown` / `SequencerGracePeriodNotOver` / `InvalidSequencerRound`. |
| `removeOracle(asset)` | Owner, **instant** | Restrictive correction: makes `getPrice` revert rather than serve an unvetted price. |
| `setSequencerOracle(feed, gracePeriod)` | Owner, `afterDelay` (TIER_2) | Optional L2 sequencer uptime gate (`address(0)` disables it — correct on L1). Gated in both directions. |
| `transferOwnership` | Owner, `afterDelay` (TIER_2) | Two-step (`Ownable2Step`); see FIND-002. |
| `setTimelock` / `activateTimelock` / `getTimelock` | Owner | Timelock integration via `TimelockIntegrationLib` (`setTimelock` is TIER_1). |
| `renounceOwnership` | — | Permanently disabled (`RenounceOwnershipDisabled`). |

**Operator invariant (not enforced):** every feed on one module must share the same quote currency (USD, ETH, …); mixing quotes makes `OracleAssetPricer` ratios wrong by the missing FX rate.

### 5. `PRE_MULTI_DEPOSIT` hook and `MultiAssetDepositCapHook`

- New `HooksLibV2.PRE_MULTI_DEPOSIT = 13` flag and `IHook.preMultiDeposit(sender, depositAsset, depositAssetAmount, baseAssets, shares, receiver, totalAssets)`. Raised only by the multi-asset vault, only on non-base deposits, after `PRE_DEPOSIT`.
- `BaseHook` provides a no-op default (eleven `IHook` entry points now); `HookContainer` forwards it to all sub-hooks (`onlyVault`).
- **`MultiAssetDepositCapHook`** (`FLAVOUR() = 9`, `BaseOwnableHook`): lifetime per-token deposit cap in the token's own decimals.
  - Offset-by-one storage (`0` = uncapped, `n` = cap of `n − 1`), so "cap of zero" (token blocked) is distinct from "no cap".
  - Rolling sum is monotonic — withdrawals never reduce it — and records uncapped tokens too, so a cap installed later already accounts for past deposits.
  - `setDepositCap`, `removeCap`, `setHookContainer` (owner); `getDepositCap`, `getRawDepositCap`, `canDeposit` views.
  - `preMultiDeposit` writes storage, so it is gated to the vault or a configured `HookContainer` bound to the same vault (`OnlyVaultOrHookContainer`, `InvalidHookContainer`).
  - Events: `DepositCapSet`, `DepositCapCleared`, `HookContainerSet`, `PerTokenCapConsumed`.
  - Base-asset deposits are never seen here — cap those with the vault's `maxGlobalDepositAmount`.

### 6. Timelock coverage

- New contract type `CT_ORACLE_MODULE` (`bytes4(keccak256("ORACLE_MODULE"))`) seeded with `setOracle`, `setSequencerOracle`, `transferOwnership` (TIER_2) and `setTimelock` (TIER_1). `removeOracle` is instant by design.
- `CT_VAULT` gains `configureMultiAsset` (TIER_2). `removeWhitelistedAsset` is intentionally not registered.
- `Timelock.reinitializeV2()` is replaced by **`reinitializeV3()`** (`reinitializer(3)`, `UPGRADER_ROLE`), which re-seeds all artifact registries including the new oracle-module entries. Idempotent; does not touch schedules, bindings, roles, or `active`.

---

### 7. Vault internals and ERC-4626 view accuracy

- **`UserActionsLib.executeDeposit` / `executeWithdraw`**: the `_deposit` / `_withdraw` bodies of `ConcreteStandardVaultImpl` (transfer, `cachedTotalAssets` update, mint / burn, allowance spend, `Deposit` / `Withdraw` events) moved into the DELEGATECALL library to free runtime bytecode. Ordering (transfer-before-mint, burn-before-transfer) is preserved.
- **Minimum deposit enforcement moved to `UserActionsLib.preDeposit` / `preMint`**, so it applies uniformly to base and non-base deposits (the latter on the base-equivalent value). `MinimumDepositAmountNotMet` is now raised before the max-deposit check.
- **`maxMint`** (`StandardVaultHelperLib.calcMaxMint`): returns `0` when the floor-to-shares / ceil-to-assets round-trip of the remaining capacity lands below `minTxDepositAmount`.
- **`maxRedeem`** (`ConcreteStandardVaultImpl`): returns `0` when the available shares convert to fewer assets than `minTxWithdrawAmount`. Both prevent the views from advertising amounts the corresponding action would reject.

## Audit remediations (Earn v1.7)

### FIND-002 — Owner-gated controls temporarily unreachable due to hardened ownership transfer

`OracleModule` now inherits `Ownable2Step`. The timelocked `transferOwnership` only records `pendingOwner`; ownership moves once that address calls `acceptOwnership`. A mistyped or unreachable `newOwner` can no longer strand `removeOracle` and the other owner-gated functions behind a full timelock cycle — the incumbent stays owner until an accept lands.

**Tests:** `test/periphery/unit-test/OracleModuleRealTimelockTest.t.sol`.

### FIND-004 — Obscured price-check enforcement

`OracleModule.OracleSet` now carries `validateCaps` and `validateStaleness`. The numeric bounds are not zeroed when a check is disabled, so without the flags an event-driven monitor could not distinguish a config with checks switched off from a fully enforced one.

**Tests:** `test/periphery/unit-test/OracleModule.t.sol`.

### FIND-006 — Non-base deposits blocked due to unsynchronized multi-asset strategy pointer

New `StateSetterMASLib` wraps `removeStrategy` and `reconcileHaltedStrategy` so `MASLib.strategy` follows the lifecycle of the strategy it names: `removeStrategy` clears it to `address(0)`; `reconcileHaltedStrategy` moves it onto `toStrategy` (already validated registered + `Active`) or clears it on the `address(0)` loss write-off branch. `ConcreteMultiAssetDepositAsyncVault` overrides both entry points to route through the overlay (without calling `super`); plain vaults keep calling `StateSetterLib` directly.

Previously, removing or reconciling the designated strategy left the pointer dangling: every non-base `deposit` / `previewDeposit` reverted `MultiAssetStrategyNotActive` while base deposits kept working, and re-adding the same address later silently re-armed the stale pointer with no `VAULT_MANAGER` re-designation. `toggleStrategyStatus` is deliberately not wrapped — a halt is reversible and instant, so halt → unhalt self-heals rather than forcing a 24h `configureMultiAsset` repair.

**Tests:** `test/unit-test/ConcreteMultiAssetDepositAsyncVault/MultiAssetNonBaseDepositUnitTest.t.sol`.

### FIND-007 — Missing standard `Deposit` event on the non-base path

The non-base deposit path now emits the canonical `IERC4626.Deposit(sender, receiver, baseAllocated, shares)` after minting, alongside `MultiAssetDeposit` (which carries the raw token and amount). Indexers relying on the ERC-4626 issuance signal now see every share mint.

**Tests:** `test/unit-test/ConcreteMultiAssetDepositAsyncVault/MultiAssetNonBaseDepositUnitTest.t.sol`.

### FIND-009 — Non-base deposit hooks (documentation)

Clarified that `PRE_DEPOSIT` / `POST_DEPOSIT` fire on **both** base and non-base deposits (both mint the same fungible shares), with `PRE_MULTI_DEPOSIT` exclusive to non-base ones. Firing order: `PRE_DEPOSIT` → `PRE_MULTI_DEPOSIT` → mint → `POST_DEPOSIT`. The `assets` argument on `PRE_DEPOSIT` / `POST_DEPOSIT` is a base-equivalent *notional* — custom hooks must not reconcile it against `asset().balanceOf(vault)`. NatSpec added across `IHook`, `ConcreteMultiAssetDepositAsyncVault`, `MultiAssetVaultHelperLib`, and `doc/Architecture.md` §3.2.

No logic change.

## Breaking changes

### `IHook.preMultiDeposit`

`IHook` gains `preMultiDeposit(...)`. Hooks extending `BaseHook` inherit a no-op default; external integrators implementing `IHook` directly must add it.

### `Timelock.reinitializeV2` → `reinitializeV3`

The re-seeding entry point is renamed and bumped to `reinitializer(3)`. Deployed timelocks (including ones that already ran `reinitializeV2`) call `reinitializeV3()` via `upgradeToAndCall` to pick up `CT_ORACLE_MODULE` and the `configureMultiAsset` vault artifact.

### Error ordering on deposits below the minimum

`MinimumDepositAmountNotMet` is now raised in `preDeposit` / `preMint`, before `ERC4626ExceededMaxDeposit` / `ERC4626ExceededMaxMint`. Callers matching on a specific revert for a deposit that violates both bounds will see the minimum-amount error first.

### `ID()` registration

See §8. Factory registrations keyed off the previous `1.6.0` (vaults) / `1.5.1` (hooks) IDs must be re-added against the new `1.7.0` IDs before deploying the upgraded implementations.

## Migration notes

For operators upgrading existing `1.6.0` deployments:

1. **Run the `Bump Version` workflow** (`v1.6.0` → `1.7.0`) and **re-register implementations** on `ConcreteFactory` / `PeripheryFactory` under the new IDs (§8) **before** calling `upgrade` on any proxy.
2. **Upgrade the Timelock** and call `reinitializeV3()` so `CT_ORACLE_MODULE` and the `configureMultiAsset` artifact are seeded.
3. **Deploying a multi-asset vault:** deploy an `OracleModule` (bind it to the timelock as `CT_ORACLE_MODULE`) and an `OracleAssetPricer`, or use `OneToOneAssetPricer` for same-peg assets; add a `MultiAssetStrategy` to the vault; then `configureMultiAsset` → `SetPricer`, `SetMultiAssetStrategy`, `AddWhitelistedAsset` (each TIER_2).
4. **Oracle feeds:** keep one quote currency per `OracleModule`, give the base-asset feed the tightest `maxDelay`, and configure the sequencer feed on L2s.
5. **Hook implementors** not extending `BaseHook` must add `preMultiDeposit` (see Breaking changes). Custom `PRE_DEPOSIT` / `POST_DEPOSIT` hooks on multi-asset vaults must treat `assets` as a base-equivalent notional (FIND-009).
